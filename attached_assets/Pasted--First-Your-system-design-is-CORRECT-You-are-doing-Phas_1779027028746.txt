✅ First: Your system design is CORRECT

You are doing:

Phase 1 (Bootstrap)
Fetch 200 candles
Build EMA from history
Phase 2 (Live)
Update EMA using:
EMA = (close - prevEMA) × multiplier + prevEMA

✔ This is exactly how professional systems work.

So the logic is NOT the problem.

🚨 So where is the issue?

If EMA is wrong while price is correct, it is almost always one of these:

❌ ISSUE 1 — You are using WRONG candle point (MOST COMMON)

You must ensure:

👉 ONLY use CLOSE of CLOSED candle

Not:

current price
partial candle close
kline update when x=false
Correct:
if (kline.x === true) {
   use kline.close
}

If you use live candle:
👉 EMA becomes “moving target” and will drift

❌ ISSUE 2 — Timeframe mismatch

You said:

15m EMA system

But common mistake:

Data	Mistake
candles	15m
price feed	1m or tick

👉 This causes mismatch between EMA and price

✔ BOTH must be from same 15m stream

❌ ISSUE 3 — Bootstrap EMA is slightly wrong (important detail)

You said:

first 100 simple average then EMA forward

This is OK, BUT:

PROBLEM:

If you only use 200 candles:

EMA100 is okay
EMA200 is weak

Because EMA200 needs more warmup stability

✔ Better practice:
👉 fetch at least 300–500 candles

❌ ISSUE 4 — MULTIPLE EMA INSTANCES (silent killer)

In many systems this happens:

EMA stored per symbol in one place
but accidentally re-initialized on updates

Example bug:

symbolState = {} // reset accidentally

or:

worker restart resets EMA

👉 This creates “wrong EMA drift”

❌ ISSUE 5 — WRONG multiplier usage

You wrote:

2 / (100 + 1)

✔ correct

BUT common mistake:

recalculating multiplier repeatedly
or mixing EMA100 and EMA200 with same state

You must ensure:

EMA100 uses multiplier100
EMA200 uses multiplier200
❌ ISSUE 6 — PRICE used BEFORE EMA update order

Correct order MUST be:

1. get candle close
2. update EMA using previous EMA
3. store new EMA
4. compute distance

Wrong order causes lag mismatch.

🔥 MOST LIKELY ROOT CAUSE (based on your description)

If I had to bet:

👉 You are updating EMA using live candle data instead of closed candle
OR
👉 EMA is being reinitialized or overwritten somewhere

These two cause 90% of bugs.

✅ Correct “gold standard” flow
Bootstrap:
fetch 300 candles
compute EMA100 + EMA200 fully
store in Map
Live:
on candle close (x=true):
    close = candle.close

    ema100 = (close - ema100_prev) * k + ema100_prev
    ema200 = (close - ema200_prev) * k + ema200_prev

    distance = (price - ema) / ema * 100
